## Общие советы

Избегай испльзования перегруженных моно—копмпонентов.
Разбивай большие компоненты на маленькие, как только маленькие компоненты будут иметь смысл сами по себе.
Используй алиасы '@' от корня проекта при импорте компонентов.

## Придерживайся следующей структуры:

1. Для страниц создавай каталог /pages
2. Дели компоненты на common (переиспользуемые) и UI (уникальные для своих страниц и блоков компоненты) — для них создай свои директории
3. При создании нового компонента — делай директорию с его названием в стиле UpperCamelCase. Каждая директория должна содержать index.tsx/jsx файл и свой css.module, на который ссылается index.tsx.
4. При работе с .css.module файлами используй библиотеку clsx, конкатинируй динамические стили с базовыми и выноси длинные стили в соответсвующий файл стилей компонента (если строчных tailwind стилей больше 3-х )
